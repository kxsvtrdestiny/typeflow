# TypeFlow 中英文打字练习平台——最终开发需求文档

## 1. 项目概述

项目名称：TypeFlow

项目类型：中英文打字练习 Web 应用。

技术栈：Vite + React + TypeScript + TailwindCSS。

参考案例：老师提供的 typing-tutor-dist.zip（金山打字通）。

项目目标：

参考老师提供的打字练习案例，开发一个具有中英文训练、实时打字统计、主题词库管理和训练记录功能的打字练习平台。

本项目以基础功能的完整性、交互的准确性和页面的美观性为主要目标。

不需要开发后端，不需要用户登录，所有用户数据使用 localStorage 保存在浏览器本地。

## 2. 产品设计原则

1. 保留传统打字练习软件的核心训练逻辑。
2. 不需要虚拟键盘，用户直接使用电脑实体键盘输入。
3. 打字训练页面采用标准答案与用户输入上下两排显示的方式。
4. 上下两排文字必须实时同步，正确字符使用绿色突出显示。
5. 页面布局简洁、清晰、美观，不要过度装饰。
6. 优先保证中文输入法兼容性。
7. 优先完成基础功能，不要为了增加功能而引入不必要的复杂度。

这是整个项目的核心页面。

支持：

- 中文训练。
- 英文训练。
- 主题选择。
- 具体文章选择。
- 随机选择文章。
- 自由练习。
- 限时挑战。
- 1、3、5、10 分钟限时选项。

#### 核心显示区域

不需要虚拟键盘，不需要显示键盘按键图案。

用户直接通过系统实体键盘输入。

页面采用上下两排文字布局：

第一排：标准答案。

第二排：用户实际输入的内容。

必须保证上下两排逐字符同步。

显示规则：

- 已正确输入的字符：绿色。
- 错误输入的字符：红色。

上下两排必须保持相同的字符位置和换行位置。

建议采用 Unicode 字符分段 + 统一字符索引 + 对应字符占位的方式实现，不能简单地将两个普通文本框上下排列。

支持：

- 实时输入。
- 实时匹配。
- 实时颜色变化。
- 自动滚动。
- Backspace。
- Enter。
- 暂停。
- 继续。
- 重新开始。
- 完成后自动结束。

#### 中文输入法处理

必须正确支持 Windows 中文输入法。

重点处理：

- compositionstart
- compositionupdate
- compositionend
- input

不能在拼音组合期间就进行正式的字符错误判定。

只有汉字真正提交后才参与训练统计。

建议使用 textarea 接收输入，通过字符分段和渲染组件实现上下两排显示。

#### 实时统计

中文模式显示：

- CPM。
- 准确率。
- 正确字符数。
- 错误字符数。
- 训练时间。
- 训练进度。

英文模式显示：

- Gross WPM。
- Net WPM。
- 准确率。
- 正确字符数。
- 错误字符数。
- 训练时间。
- 训练进度。

中文 CPM：

CPM = 正确汉字数 / 训练分钟数。

英文 WPM：

Gross WPM = 输入字符数 / 5 / 训练分钟数。

Net WPM = max(0, 输入字符数 - 错误字符数) / 5 / 训练分钟数。

准确率：

Accuracy = 正确字符数 / 已提交字符数 × 100%。

统计逻辑必须实时更新，不能出现删除字符后统计数据不更新的情况。

计时器使用真实时间差计算，不要简单依赖 setInterval 累加时间。

#### 训练结束

- 训练语言。
- 训练主题。
- 训练用时。
- 打字速度。
- 准确率。
- 正确字符数。
- 错误字符数。
- 完成进度。
- 是否刷新个人最佳成绩。

提供：

- 返回首页。

## 12. 上下两排实时同步方案（核心）

### 12.1 统一数据模型

训练文本先做固定规范化：CRLF/CR 转 LF、去除文件起始 BOM；不自动去除空格、标点，不做全角半角替换或大小写折叠。导入中的 Tab 等不可见字符提供预览和明确处理提示。训练开始后冻结文章快照，避免词库编辑影响进行中的训练。

使用 `Intl.Segmenter` 的 grapheme 模式分段；初始化时确认目标浏览器支持，必要时引入经测试的分段回退。避免使用 split('') 或仅用 Array.from 处理所有情况。汉字、拉丁字母、组合重音、emoji 均以可见字符簇为匹配单位；输入选择区的 UTF-16 偏移与字符簇索引建立双向映射。

标准答案和正式输入共享同一个位置索引。默认采用逐位置严格比较，不做自动纠错或编辑距离对齐：漏字后后续字符会顺移判错，Backspace 修正后重新匹配。这一规则写入 UI/README。

### 12.2 一个网格，两层内容

不能使用两个各自换行的普通文本容器。先将标准字符和用户字符映射为同一组 slot，再依据可用宽度把 slot 分为逻辑行；每行包含标准行和输入行，每个 slot 的上、下单元格使用相同宽度。

初版使用统一固定宽度字符格和统一行高，保证中文、英文、空格和错误字符始终同列；英文也按字符格展示。过宽字符需有一致的 slot 宽度策略，两层同时应用，不能依赖字体碰巧等宽。空格保留占位，换行用显式结束标记显示；原文 LF 强制断行，用户 LF 在对应格显示，不能触发下排独立换行。

- 标准与输入正确位置绿色，错误位置红色并辅以图形/下划线，未输入标准字符灰色，当前位置蓝色。
- 下排未输入位置仍保留空格占位，末尾提供光标格；超出标准文本的输入进入额外格并标错，不静默丢弃。
- ResizeObserver 重新计算每行容量，两层一次性使用同一结果；保留当前字符锚点。
- 当前字符定位到所属成对行，只有一个滚动容器；必要时滚动当前行，避免每次输入都抢滚动。窗口缩放、删除、长文和组合输入均检查定位。
- 可视层不接管原生输入法。textarea 保留焦点和可访问标签，不能 display:none；原生光标/候选窗口位置尽量贴近当前输入格，通过布局测量同步位置。视觉层避免重复朗读整篇文章。

## 13. 中文输入法与编辑事件方案（核心）

textarea 使用受控边界之外的原生编辑缓冲：让浏览器先更新 DOM，通过 ref 和事件读取完整 value。组合输入时不强制重写 value、不移动 selection、不重挂载 textarea，避免中断候选词。React 中分别保存正式快照和预编辑展示状态。

事件流程：

1. compositionstart 标记 composing，保存组合前正式快照及选择区。
2. compositionupdate 仅更新预编辑展示和候选位置，不判错、不计字符、不发正确/错误音效、不触发完成。
3. input 在 composing 或 InputEvent.isComposing 为真时只同步预编辑；其余情况读取 textarea 全量内容，分段后替换正式快照。
4. compositionend 结束预编辑，读取原生最新值并安排一次幂等提交；随后浏览器可能再发 input。以值快照/修订号去重，防止一次汉字提交统计两次。
5. 不把 keydown.key 当成正式文本来源，不拦截系统候选选择用的 Space、Enter、数字；兼容 keyCode 229 等异常组合顺序，仅作为兼容保护，不能作为唯一依据。
6. 非组合期间 Backspace、Delete、选区替换、光标移动、Enter 由 textarea 原生处理；提交后从完整值重算位置状态和统计。Backspace 可能删除一个 Unicode 码元或组合序列，最终以实际 value 为准。
7. 训练默认禁用拼写修正、自动大写和自动补全。练习区禁止粘贴/拖入以避免虚增成绩，词库编辑区允许复制粘贴；移动端和不支持 inputType 的浏览器需验收。未支持的撤销/编辑事件不得悄悄破坏字符映射。

暂停或切换页面时，组合中的拼音不计入正式成绩；保留最后正式快照，明确结束输入焦点，继续时从正式快照恢复。限时到期必须立即结束计时，忽略截止后才提交的候选字，不因为等待 compositionend 延长成绩。重新开始清空所有组合、选择、计时及结束标记。切换文章/模式时，对进行中的训练提示避免误丢输入。

云端自动化可以验证组合事件序列、去重、提交统计和渲染，但不能证明真实 Windows 输入法候选窗口行为。最终需在 Windows 的 Chrome/Edge 使用微软拼音，检查多字候选、Space/Enter/数字选词、候选取消、组合中退格、快速连输、暂停/到期边界和候选窗位置；可补测搜狗输入法。手机真实输入法和 Safari 同样单列未验证项。

## 14. 统计、计时与持久化口径

- 正确数 C：当前正式输入中与标准对应位置完全相等的字符簇数；错误数 E：错误位置加额外输入位置；N=C+E。删除、替换后从当前快照重算，不累计已经删除的错误。
- 准确率为 C/N×100%；N=0 时显示“—”。中文 CPM 严格按原需求使用“正确汉字数/有效分钟”，标点、空格、数字不计 CPM 分子，但计入逐字符匹配及准确率；组合字符中的汉字按 Unicode Script=Han 判定并测试。
- 英文 Gross WPM=N/5/有效分钟；Net WPM=max(0,N-E)/5/有效分钟。字符计数与分段一致，空格和换行计入；时间为零时速度显示 0。保留精度计算，界面统一舍入。
- 进度为 min(N,标准长度)/标准长度，表示已输入位置覆盖率；准确率单独表达正确程度。默认正式输入达到文章长度即结束，允许保留错误成绩；组合中不提前结束。整段候选提交产生的额外字符全部记错。空文章禁止开始。
- 首次非空正式提交启动计时（候选拼音不启动），`performance.now()` 测量有效耗时并扣除暂停；setInterval/requestAnimationFrame 只触发显示更新，不作为累计时间来源。
- 限时截止使用绝对 deadline，每次输入、恢复和页面可见性变化均检查；后台标签页时间仍计入，暂停时间不计。到期结算按设定时长封顶；以 finishOnce 防重复写入。
- 有效完成默认为有正式输入且有效时间大于零，文章完成或限时到期各保存一次；暂停、重新开始、离开不保存成绩。默认自动保存开启，关闭时不写历史且界面明确提示。
- 最佳成绩按中文 CPM 和英文 Net WPM 分别比较，只比较已保存有效记录，不混用单位；首条记录建立基准。自由练习与限时成绩展示模式标签，后续若要限定排行榜规则需另行确认。
- 错误字符分析先采用结束时仍存在的错误：记录预期字→实际字及次数，避免把已修正错误误称最终错误；不额外存储全部按键。每日目标按用户浏览器本地自然日计算，跨午夜按实际训练区间分配时长，暂停不计入。
- Zustand persist/localStorage 使用带版本 schema 的命名空间；仅持久化自定义主题、设置、历史及必要汇总，默认词库只读，进行中的输入不持久化。派生统计尽量从记录计算，防止多个副本漂移。
- 处理损坏 JSON、旧版本、容量不足及禁用存储，提示降级/保存失败，不能假装保存成功。删除记录后更新首页、最佳成绩、每日目标和错误分析；重置需明确确认，恢复默认词库与设置。

## 15. 文件导入与内容约束

TXT 默认 UTF-8，处理 BOM；乱码时允许明确选择 GB18030 重新读取（浏览器支持时），不无提示猜测编码。DOCX 使用 Mammoth extractRawText，作为纯文本渲染，不注入生成的 HTML。预览、字符统计、编辑、确认保存走同一分段和规范化逻辑。

限制文件大小和解压后文本长度，拒绝损坏 DOCX、空文本及超限文件，展示可理解的错误；具体上限在实现时设为公开常量并写入提示。MD 可作为纯文本导入的可选项，不能挤占必需功能。

默认内容至少 12 个主题、60 篇完整文章，中英每主题至少 5 篇；使用原创或可合法使用的文本，避免伪造新闻或未经许可搬运长文。训练内容的数量、非空、唯一 ID 和语言归属由测试验证。
